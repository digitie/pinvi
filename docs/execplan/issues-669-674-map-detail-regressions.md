# #669·#674 지도 선택·팝업·상세 회귀

## 범위

- #671/#672는 다른 Code가 진행 중이라는 사용자 지시에 따라 건너뛴다. 중복 draft676은 닫고 로컬 수정은 stash로 보관했다.
- #669 선택한 두 외부 보강을 단일 상세 예산 안에서 병렬 실행한다. 이미 완료된 결과를 보존하고 미완료만 저하로 표시하며 요청 순서를 유지한다.
- #674 검색 결과 선택의 실제 이동, 모바일 여행 전체 맞춤 범위, 교통 패널에 가려지는 popup 닫기를 재현한다.
- 제품 결함과 오래된 fixture·대기 조건의 잘못을 구분한다. 데이터가 맞지 않는 합격 조건을 단순 완화하지 않는다.

## 순서와 검증

1. API 보강의 동시 시작·시간 예산·부분 결과·취소·순서 회귀를 먼저 작성한다.
2. 실제 WSL API·Chromium에서 검색 이동·여행4장소 맞춤·popup 상호작용을 확인하고 재현한 원인을 수정한다.
3. 관련 카탈로그를 실제 응답·카메라 완료·DOM 클릭 가능성에 연결한다. 운영 origin guard는 유지한다.
4. 의미 있는 구현을 자주 remote에 커밋한다. 최종 독립 전문 적대 리뷰2인·최종 SHA CI 후 일반 squash merge한다.

## 경계

- 기존 색상·톤·공유/숨김 정책을 보존한다.
- prod 접근·배포·운영 테스트는 하지 않는다. 최종 운영 검증은 Claude Code가 담당한다.
- 실제 Telegram 등 외부 메시지를 보내지 않는다. 원문 운영 값은 커밋하지 않는다.

## 구현·재현 결과

- 단일 상세 예산 안의 TaskGroup 병렬 보강·부분 결과·순서·취소·잘못된 응답 격리를 검증했다.
- 검색어 변경 즉시 이전 결과를 지우고 취소를 무시한 응답도 폐기한다. 명시적 검색 이동은 늦은 위치 응답으로 덮이지 않는다. 좌표 없는 feature는 정본 상세로 연결한다.
- 실제 popup 가림과 배경 닫기 후 재선택 결함을 실패 우선으로 확인했다. 앱 popup 계층20과 소유 상태 동기화, 도형 선택 revision으로 해결했다. 팝업도 제한된 detail-card·공개 오류·부분 상태를 사용한다.
- 실제4개 POI는 초기844px/390px에서 모두 포함됐다. 운영 모바일 맞춤 원인은 재현하지 못했으므로 resize 제품 코드를 추가하지 않았다. 검색 fixture는 현재 HTTP의 정확 일치·좌표 있는 행으로 제한하고 실제4좌표를 bbox와 비교한다.
- WSL 실제 UI11흐름·API20·웹351·mypy256·타입·Ruff·lint(기존5경고)·카탈로그346/자동298을 확인했다. 안전한 증거와 소스 지문은 docs/reviews/pinvi-669-674-map-detail-wsl-live.json에 있다.
- 남은 게이트: 최종 커밋의 전문 적대 리뷰2인, CI 전체, 미해결 원격 리뷰 확인, 일반 squash merge. 운영 최종 검증은 Claude Code가 담당한다.

## 최종 리뷰 보완

- 여행 검색은 상세 열기 capability가 없어 좌표 없는 feature를 추가할 수 없다. 상세 capability를 명시한 탐색만 활성 상세 행을 제공한다.
- 새 실패 우선 회귀와 WSL 실제 UI의 null 행 비활성·정상 좌표 POST201/목록5개를 추가했다. 웹352·실제 UI12흐름을 통과했다. 최종 manifest가 이전 관측·소스 지문을 대체한다.
