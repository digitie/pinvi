# #673/#675 날짜 날씨 요약·관리자 조회 정합성

## 범위와 경계

- 날짜 요약이 앞의 두 지표만 잘라 체감온도 두 제공자가 핵심 기온·하늘·강수를 가리는지 실패 우선으로 확인한다. 알려진 지표·단위를 사람이 읽게 표시하고, 없는 사실·provider별 코드 의미는 지어내지 않는다.
- 관리자 weather-values가 사용자 Map 모드와 다르게 direct만 읽는 ADR-077 예외를 재검토한다. 동일 설정의 소스를 사용하되 admin 상세의 비공개 좌표 접근과 RBAC를 보존한다.
- Map에 없는 원천 dataset key는 null로 보존한다. stale 신호를 실제 선택한 값에서 가져오고 로딩·빈 값·메타 부재를 fresh로 부르지 않는다.
- 운영 접근·배포·테스트는 하지 않는다. 최종 운영 검증은 Claude Code 담당이다. 색상·톤은 유지한다.

## 순서

1. draft PR을 먼저 만들고 관련 API·웹 회귀 실패를 확인한다.
2. 공통 수집 경계·취소·예산을 지키며 Map/direct 소스와 요약 선택·포맷을 맞춘다. 직접 조회 장애에서 남는 병렬 작업도 회수한다.
3. 실제 WSL Map/PostGIS·Valkey·API·Next·Chromium에서 날짜 요약과 관리자 표·미확인 신선도를 검증한다.
4. 문서·카탈로그·journal/resume를 갱신하고 자주 remote에 커밋한다. 최종 전문 적대 리뷰2인·CI 후 일반 squash merge한다.
