# pip build isolation 환경 제약(Dockerfile·CI의 `--build-constraint`). 앱 의존성이 아니다 —
# 그것은 `uv.lock`이 정본이다. 여기는 소스에서 빌드되는 두 가지의 build 환경만 `==`로 고정한다.
#
# - `-e .`: pyproject `[build-system]`의 hatchling과 그 의존성, 그리고 hatchling의 editable
#   훅이 **추가로** 요구하는 `editables`("Getting requirements to build editable" 단계에서 받는다).
# - git 의존성(`uv.lock`의 `source = { git = ... }`, 지금은 python-kasi-api): 그 저장소
#   `[build-system]`의 setuptools·wheel과 그 의존성(wheel → packaging).
#
# 올릴 때는 목록부터 다시 뽑는다 — 같은 base 이미지에서 `pip install pip==<고정 버전>` 후
#   pip install -v --no-deps --no-cache-dir --dry-run -e .
#   pip install -v --no-deps --no-cache-dir --dry-run "python-kasi-api @ git+<uv.lock의 커밋>"
# 의 "Installing build dependencies"와 "Getting requirements to build editable" 아래
# `Successfully installed` 줄이 필요한 전체 집합이다(빌드 훅이 동적으로 요구하는 것까지 나온다).
# 그 집합을 깨끗한 venv에 `==`로 설치하고 `pip freeze`로 이 파일을 통째 바꾼다.
