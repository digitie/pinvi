# #667 삭제 첨부의 저장 공간·수명

## 확인한 문제

활성 부모만 세는 쿼터와 실제 RustFS 객체 보존이 달라 삭제·재업로드로 저장 공간 상한을 우회한다. 직접 삭제된 첨부도 객체를 보존한다. 복사된 여행은 같은 저장소 키를 참조하므로 객체 삭제 시 다른 활성 참조를 보존해야 한다.

## 공통 구현

실제 보존 중인 첨부는 삭제된 부모·첨부라도 쿼터에 반영한다. 목록·다운로드의 활성 부모 접근 제한은 유지한다. 실제 저장 공간을 늘리지 않는 복원은 새 업로드와 구분한다. 기존 사용자·여행의 총량 잠금과 대조 계정도 검증한다.

## 보존 정책 결정

사용자가 2026-11-05 휴지통 30일 보존 후 영구 삭제·파일 GC까지 구현하도록 확정했다. 기존 공통 수정 위에 아래 수명 관리를 추가한다.

## 검증과 순서

draft를 먼저 만들고 자주 원격에 커밋한다. 실패 우선 PostgreSQL 회귀, WSL 실제 UI, 두 독립 전문 적대 리뷰, 최종 HEAD CI 뒤 일반 squash merge한다. 운영 접근·배포·실제 계정 데이터 변경은 없으며 최종 prod 검증은 Claude Code 담당이다.

## 직전 완료

#653은 Manager582(20868ab3) 다음 Pinvi680(bbabe45a)로 병합했다. 최종 두 리뷰 무차단·CI 통과, WSL API48·웹376·실제 UI9흐름, Manager 관련43·daemonless3610통과40건너뜀을 기록했다. Docker 포함 추가 탐색의 기존 Dagster 테스트 전제 불일치와919통과 중단은 Manager PR에 별도 기록했다.

## 공통 수정 검증

삭제 여행·POI·직접 삭제 첨부의 사용자 총량과 직접 삭제 첨부의 여행 총량4회귀가 기존 구현에서 실패했다. 보존 총량 반영과 비증가 복원으로 바꾼 뒤 관련19개·Ruff를 통과했다. UI/보존 정책 결정·최종 두 리뷰/CI는 남아 있다.


## 초기 리뷰 보완

일자 하드 삭제의 FK CASCADE와 복사/합치기 quota 미검사를 두 리뷰어가 발견했다. 삭제 전 보존 참조를 soft delete된 여행 첨부로 옮기며, 관리자 일자 이동/삭제도 여행 잠금 후 같은 절차를 따른다. 복사 대상 여행→사용자 잠금으로 추가 총량을 검사하고 실패하면 새 여행·일자·POI·첨부를 모두 롤백한다.

빈 일자 fixture 오류를 수정한 실제 일자 소실2실패, 복사2실패를 추가로 확인했다. 현재 관련API72·mypy256·웹376·타입/lint(기존5경고)를 통과했다. 전체 이슈의 UI·보존 정책·최종 두 리뷰/CI·머지는 아직 남아 있다.


## 추가 공통 보완

관리자 일자/POI 부분 복사도 실제 admin 업로더의 capacity를 검사한다. 활성 파일이 목적지에 남고 기존 삭제 첨부는 비공개/과금/삭제 시각을 유지하는 move 정책 대조를 추가했다.

POI 사전 검사 후 관리자 이동과 업로드가 겹치는 Event 회귀2건에서 기존201허용을 확인했다. 등록 직전 대상 여행 잠금/refresh 뒤 쓰기 권한과 POI·일자 소속을 다시 확인하며 POI 행을 잠근다. 변경된 대상은 기존 INVALID_ATTACHMENT_STORAGE_REF(422)로 거부하고 다른 비공개 여행의 첨부/사용량은 늘리지 않는다. 관리자 POI 이동·삭제도 정렬된 여행→POI 잠금을 따른다.

관련API85·mypy256 통과. 웹376·타입/lint는 같은 웹 소스에서 통과했다. 실제 UI·보존 정책·최종 전체 승인/CI·머지는 남아 있으며 draft를 유지한다.


## 확정 수명 설계

- 여행 삭제 후 30일까지만 복원한다. 기한이 지나거나 정리가 시작된 여행은 복원하지 않는다. 정리 시작 표식은 되돌리지 않는다.
- 첨부는 물리 정리 확인 전까지 과금한다. 공유 객체에 다른 활성/복원 가능 참조가 있으면 그 객체를 보존하고 삭제 대상의 참조만 정리한다.
- 객체별 DB advisory 잠금으로 등록·복사·업로드와 정리 시작을 직렬화한다. 영구 tombstone이 생긴 키는 새 참조/업로드를 거부한다. DB tombstone 커밋 뒤에만 실제 객체를 삭제한다.
- 영속 큐의 lease/시도 횟수/안전한 오류 코드로 실패·프로세스 중단을 재시도한다. lease가 끝난 옛 worker와 새 worker가 겹쳐도 같은 영구 폐기 키만 삭제한다.
- 업로드 URL 발급을 기록하고 미등록 예약 용량도 사용자 한도에 포함한다. 등록 시 같은 트랜잭션에서 예약을 첨부 과금으로 바꾸고, 만료된 미등록 업로드도 GC한다. 역사적 미기록 객체를 추정해 삭제하지 않는다.
- 관리자 전용 dry-run/실행/상태 UI를 제공한다. 실행 사유·확인 문구·감사 기록을 남기며 한 번의 실행량은 제한한다. 전체 영수증 대신 집계와 비밀 없는 오류 코드만 노출한다.
- 새 app migration과 M05 revision 계약·런타임 권한·정본 문서를 함께 갱신한다. WSL 실제 RustFS·PostgreSQL·UI와 두 독립 리뷰 후 최종 CI·머지를 수행한다.


## 영속화·실제 검증 checkpoint

- 업로드 시작 표식을 네트워크 호출 전에 커밋하고 같은 키의 재사용을 거부한다. 완료 기록이 유실된 업로드는 등록하지 않으며, 결과 불확실성 보호 기간과 영구 tombstone 재확인으로 늦게 남은 객체를 다시 정리한다. 이를 정확히 한 번 처리나 순간 물리 저장량의 보장으로 주장하지 않는다.
- RustFS versioning의 과거 버전·삭제 표식을 실제로 제거하고 인접 키를 보존한다. 실제 로컬 RustFS 버전 2개 삭제 대조를 통과했다. 자동 GC와 별개인 기존 관리자 force 삭제의 특권 우회 의미는 유지한다.
- 신고 처리 이력에서 복원 대기 보존을 구분하고, 최상위 부모가 만료된 경우 정리한다. 신고 FK와 여행 정리의 잠금 충돌은 제한 시간·재시도 코드로 처리한다. 복사의 전체 객체 잠금 순서를 통일하고 사라진 원본 참조를 다시 검사한다.
- 강화한 PostgreSQL/API55개와 mypy261개 파일, 웹381개·타입 검사를 통과했다. 웹 lint의 관리자 모달 경계 위반을 기존 admin alert-dialog로 교체한 뒤 관련9개·타입·lint(기존5경고)를 통과했다.
- WSL 실제 Map/PostGIS·Pinvi API·Next/Chromium·RustFS UI7흐름과 물리 객체3건 대조를 통과했다. 업로드·복원 기한/API410·보존 쿼터/UI 오류·사유/문구/확인·정리·다른 사용자 복사본 다운로드·용량 회복을 포함한다. 소유 테스트 스택은 종료했다. 모달 교체 뒤 실제 UI는 다시 확인해야 한다.
- #643 최신 본문과 개별 상태를 다시 확인했다. 남은 이슈는 #667/#668/#650/#636/#637/#638/#641이며 Telegram3건은 묶을 수 있다. #671/#672는 다른 Code가 처리했다.
