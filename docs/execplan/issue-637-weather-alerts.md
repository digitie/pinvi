# #637 여행 기상특보 Telegram 알림

## 목표와 경계

여행 기간 중 대표 법정동 primary_region에 적용되는 명시적 특보 발표 관측을 기존 Telegram 대상별 발송 이력과 오류 화면에 연결한다. POI 좌표와 BJD를 추정 변환하지 않는다. 원천 수집·지역 매핑은 Weather201이 소유한다. 병합된 owner OpenAPI를 먼저 동기화한 뒤 소비한다.

기존636/638 일정·예약과 같은 사용자 기본 off 설정에 weather_enabled를 추가한다. 현재 소유 여행·계정·동의·기간·대표 지역·검증 대상/연결 generation을 생성과 각 chunk 직전 재확인한다. 공식 발표와 의미별 여행 중복을 영속 발생키로 막는다. 해제는 명시적 해제 관측만 사용하며 취소·변경은 해제와 구별한다. 원천의 occurrence_id는 미확정이며 회차를 추정하지 않는다.

최신성·지역 확인·조회 완결성을 확인하고, 알 수 없거나 실패한 경우 발송하지 않으며 안전한 상세 원인을 UI에 남긴다. 개별 사용자 오류가 뒤 사용자의 계획을 막지 않도록 한다. 지연된 옛 발표를 신규 실시간 경보처럼 발송하지 않도록 시간 경계를 정의하고 검증한다.

## 진행과 검증

초안 PR 먼저, 기능별 원격 커밋을 남긴다. WSL 실제 Postgres/API·소유 Weather/Telegram TCP fixture·프로덕션 웹 Chromium으로 opt-in·발령·명시 해제·실패 원인·중복/철회 경계를 검증한다. 색상은 유지한다. 원천/provider 직접 파싱·실제 Telegram 전송·운영 접근·배포·시험은 하지 않는다.

독립 전문 적대 리뷰2인을 거쳐 지적을 실패 우선으로 보완하고, 정확 최종 HEAD의 모든 적용 CI가 성공하면 일반 squash merge한다. 후속 #641은 별도 PR, #650/Map1450 운영 최종 검증은 Claude Code 담당이다. #671/#672와 보호 stash는 건드리지 않는다.

## 소비자 세부 경계

- 대표 BJD와 현재 KST 여행 시작·종료가 있는 여행만 대상으로 한다. 날짜 미정·기간 밖·지역 미확인은 보내지 않으며 원인을 이력에 남긴다.
- weather_enabled_at을 별도 저장한다. 최초 활성화·재활성화 전 과거 발표를 소급 전송하지 않는다. 꺼진 상태는 null이고 현재 generation을 각 chunk 직전에 확인한다.
- 최근1시간의 최초 관측 구간을 반복 조회하며 공식 발표가 최근30분 안이고 동의 이후인 관측만 후보로 삼는다. 메시지는 현재 활성 상태를 보장하지 않는 '공식 발표'와 발표·발효 시각을 명시한다.
- 같은 공식 announcement_id의 취소는 영속 tombstone으로 보존한다. 서로 다른 비취소 관측은 순서를 추정하지 않고 모호성으로 미발송한다. 취소 관측을 일반 해제로 바꾸지 않으며, 서로 다른 발표를 가짜 회차로 연결하지 않는다.
- 발생키는 여행·announcement_id·action으로 만들며 재조회·재실행에도 하나만 만든다. 한 후보의 수신 대상 snapshot은 최초 생성 이후 늘리지 않는다.
- HTTP 전송 만료는 생성15분·공식 발표30분·여행 종료 KST 자정 중 가장 이른 시각이다. 같은 여행 기간 안의 자정 경과 자체로 최근 경보를 무효화하지 않는다.
- 현재 대표 지역·기간·소유권·계정·동의·연결을 발송 시 다시 확인한다. 중간의 대표 지역/날짜 변경은 예전 알림을 생략한다. 정책 잠금 대기 중 기간이 끝난 경우 HTTP 직전에 만료를 확인한다.
- owner의 fresh·events_complete·region_status·namespace·요청 BJD 일치를 검증한다. 부분 매핑을 전체 지역 안전이나 해제라고 표현하지 않는다. 알 수 없는 action은 발송하지 않는다.
- 오류 코드는 고정 allowlist의 한국어 설명만 저장한다. 원문 provider 응답·URL·토큰은 UI와 공개 이력에 넣지 않는다. 반복 오류는 여행·오류·시간대별로 중복을 제한하고 이후 성공을 막지 않는다.
